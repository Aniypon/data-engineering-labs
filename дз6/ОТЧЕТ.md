### Архитектура
```
Controller → Service → Repository → Database
     ↓         ↓          ↓
   REST     Business    Data
   API      Logic     Access
```

### Основные компоненты

#### 1. Entities (JPA Сущности)
- `Category.java` - категории товаров
- `Product.java` - товары с привязкой к категориям
- Двунаправленные связи @OneToMany/@ManyToOne
- Аннотации @JsonIgnore для предотвращения циклических ссылок

#### 2. DTOs (Data Transfer Objects)  
- `ProductCreateRequest` - создание товара
- `ProductUpdateRequest` - обновление товара
- `CategoryCreateRequest` - создание категории
- `ProductWithCategoryResponse` - ответ с JOIN данными

#### 3. Repositories
- `ProductRepository` с custom JPQL запросом для JOIN
- `CategoryRepository` с базовыми CRUD операциями

#### 4. Services  
- `ProductService` - бизнес-логика товаров
- `CategoryService` - бизнес-логика категорий

#### 5. Controllers
- `ProductController` - REST API для товаров  
- `CategoryController` - REST API для категорий

### 1. Получение товаров с категориями (JOIN запрос) 
**Назначение**: Демонстрирует JOIN операцию между таблицами Product и Category
**Endpoint**: `GET /api/products/with-categories`

```bash
curl -s http://localhost:8888/api/products/with-categories | jq .
```

**Результат**:
```json
[
  {
    "id": 1,
    "name": "iPhone 15",
    "description": "Новейший смартфон от Apple",
    "price": 89990.00,
    "stockQuantity": 25,
    "imageUrl": "/images/iphone15.jpg",
    "categoryName": "Смартфоны"
  },
  {
    "id": 2,
    "name": "Samsung Galaxy S23",
    "description": "Флагманский Android-смартфон",
    "price": 75990.00,
    "stockQuantity": 30,
    "imageUrl": "/images/samsung_s23.jpg",
    "categoryName": "Смартфоны"
  },
  {
    "id": 3,
    "name": "MacBook Pro 16\"",
    "description": "Мощный ноутбук для профессионалов",
    "price": 199990.00,
    "stockQuantity": 10,
    "imageUrl": "/images/macbook_pro.jpg",
    "categoryName": "Ноутбуки"
  }
]
```

**Пояснение**: Запрос выполняет INNER JOIN между таблицами products и categories, возвращая все товары с названиями их категорий. Используется кастомный JPQL запрос в ProductRepository.

### 2. Создание новой категории
**Назначение**: Создание новой категории товаров  
**Endpoint**: `POST /api/categories`

```bash
curl -X POST http://localhost:8888/api/categories \
  -H "Content-Type: application/json" \
  -d '{"name": "Игровые консоли", "description": "Консоли для видеоигр"}'
```

**Результат**:
```json
{
  "id": 11,
  "name": "Игровые консоли",
  "description": "Консоли для видеоигр",
  "parentId": null,
  "imageUrl": null
}
```

**Пояснение**: Создается новая категория с автоматически сгенерированным ID. Поля parentId и imageUrl остаются null, так как не были переданы в запросе.

---

### 3. Создание товара с привязкой к категории
**Назначение**: Создание нового товара и сразу привязка его к существующей категории
**Endpoint**: `POST /api/products`

```bash
curl -X POST http://localhost:8888/api/products \
  -H "Content-Type: application/json" \
  -d '{
    "name": "PlayStation 5", 
    "description": "Игровая консоль Sony следующего поколения", 
    "price": 49990.00, 
    "stockQuantity": 5, 
    "categoryId": 11
  }'
```

**Результат**:
```json
{
  "id": 11,
  "name": "PlayStation 5",
  "description": "Игровая консоль Sony следующего поколения",
  "price": 49990.00,
  "stockQuantity": 5,
  "imageUrl": null,
  "createdAt": "2025-06-04T13:58:17.556564836",
  "updatedAt": null
}
```

**Пояснение**: Товар создается с указанием categoryId=11 (созданная ранее категория "Игровые консоли"). Автоматически устанавливается timestamp createdAt, updatedAt остается null до первого обновления.

---

### 4. Редактирование полей товара  
**Назначение**: Обновление информации о существующем товаре
**Endpoint**: `PUT /api/products/{id}`

```bash
curl -X PUT http://localhost:8888/api/products/11 \
  -H "Content-Type: application/json" \
  -d '{
    "name": "PlayStation 5 Pro", 
    "description": "Улучшенная версия игровой консоли Sony", 
    "price": 59990.00, 
    "stockQuantity": 3
  }'
```

**Результат**:
```json
{
  "id": 11,
  "name": "PlayStation 5 Pro",
  "description": "Улучшенная версия игровой консоли Sony",
  "price": 59990.00,
  "stockQuantity": 3,
  "imageUrl": null,
  "createdAt": "2025-06-04T13:58:17.556565",
  "updatedAt": "2025-06-04T13:59:00.744325634"
}
```

**Пояснение**: Обновляются название, описание, цена и количество товара. Поле updatedAt автоматически устанавливается в текущее время при любом изменении.

---

### 5. Привязка товара к другой категории
**Назначение**: Изменение категории существующего товара
**Endpoint**: `PUT /api/products/{productId}/category/{categoryId}`

```bash
curl -X PUT http://localhost:8888/api/products/11/category/3
```

**Результат**:
```json
{
  "id": 11,
  "name": "PlayStation 5 Pro",
  "description": "Улучшенная версия игровой консоли Sony",
  "price": 59990.00,
  "stockQuantity": 3,
  "imageUrl": null,
  "createdAt": "2025-06-04T13:58:17.556565",
  "updatedAt": "2025-06-04T13:59:10.180533805"
}
```

**Пояснение**: Товар с ID=11 переносится в категорию с ID=3 ("Ноутбуки"). Обновляется поле updatedAt. Foreign key в таблице products изменяется на новое значение.

---

### 6. Проверка результата JOIN запроса
**Назначение**: Подтверждение, что изменения отражены в JOIN запросе
**Endpoint**: `GET /api/products/with-categories` (фильтрация по ID=11)

```bash
curl -s http://localhost:8888/api/products/with-categories | jq '.[] | select(.id == 11)'
```

**Результат**:
```json
{
  "id": 11,
  "name": "PlayStation 5 Pro",
  "description": "Улучшенная версия игровой консоли Sony",
  "price": 59990.00,
  "stockQuantity": 3,
  "imageUrl": null,
  "categoryName": "Ноутбуки"
}
```

**Пояснение**: В результате JOIN запроса видно, что товар PlayStation 5 Pro теперь принадлежит категории "Ноутбуки" (была изменена в предыдущем шаге).
