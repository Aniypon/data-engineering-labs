## 1. Обоснование выбора таблицы orders для партиционирования

### Критерии выбора:
- **Естественный ключ партиционирования**: `created_at` (временная метка создания заказа)
- **Логическое разделение данных**: заказы естественно группируются по времени
- **Паттерны доступа**: 
  - Новые заказы обрабатываются активно
  - Старые заказы запрашиваются реже (отчеты, архив)
  - Аналитические запросы часто фильтруются по периодам
- **Производительность**: PostgreSQL может исключать ненужные партиции при выполнении запросов
- **Масштабируемость**: таблица заказов растет постоянно и может стать очень большой

### Преимущества партиционирования orders:
1. **Constraint Exclusion**: PostgreSQL автоматически исключает нерелевантные партиции
2. **Быстрое удаление данных**: `DROP PARTITION` вместо медленного `DELETE`
3. **Параллельная обработка**: возможность параллельного сканирования партиций
4. **Архивирование**: простое перемещение старых партиций в архив
5. **Индексация**: более эффективные индексы на меньших наборах данных

## 2. Реализованная схема партиционирования

### Тип партиционирования: RANGE по полю created_at
- **Период**: месячные партиции
- **Именование**: `orders_YYYY_MM` (например, `orders_2025_01`)
- **Автоматическое создание**: через BEFORE INSERT триггер

### Структура партиционированной таблицы:
```sql
CREATE TABLE orders (
    id SERIAL,
    order_number VARCHAR(20) UNIQUE NOT NULL,
    user_id INTEGER NOT NULL,
    status VARCHAR(20) NOT NULL,
    total_amount DECIMAL(10,2) NOT NULL,
    shipping_address TEXT NOT NULL,
    payment_method VARCHAR(50),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id, created_at),  -- created_at включен в PRIMARY KEY
    FOREIGN KEY (user_id) REFERENCES users(id)
) PARTITION BY RANGE (created_at);
```

## 3. Триггер автоматического создания партиций

### Функциональность:
- **Автоматическое создание**: партиции создаются при первой вставке данных за месяц
- **Именование**: автоматическое формирование имени партиции
- **Индексирование**: автоматическое создание индексов для новых партиций
- **Логирование**: информационные сообщения о создании партиций

### Ключевые функции:
1. `create_partition_if_not_exists()` - основная функция триггера
2. `create_partitions_for_period()` - создание партиций заранее
3. `drop_old_partitions()` - очистка старых партиций

## 4. Хранимые процедуры

### Аналитические процедуры:
1. **`get_orders_analytics()`** - аналитика заказов по периодам
   - Количество заказов
   - Общая выручка
   - Средний чек
   - Уникальные клиенты
   - Популярный статус

2. **`get_partition_statistics()`** - статистика по партициям
   - Общее количество партиций
   - Распределение данных
   - Самая большая партиция

### Управленческие процедуры:
1. **`update_order_status_bulk()`** - массовое обновление статусов
2. **`archive_old_orders()`** - архивирование старых заказов
3. **`check_partition_integrity()`** - проверка целостности партиций

## 5. Производительность и оптимизация

### Созданные индексы для каждой партиции:
- `idx_orders_YYYY_MM_created_at` - основной индекс по времени
- `idx_orders_YYYY_MM_user_id` - индекс по пользователю
- `idx_orders_YYYY_MM_status` - индекс по статусу
- `idx_orders_YYYY_MM_order_number` - индекс по номеру заказа

### Оптимизации:
- **Constraint Exclusion**: включено в PostgreSQL по умолчанию
- **Статистика**: автоматический сбор статистики для оптимизатора
- **Параллелизм**: возможность параллельного сканирования партиций
